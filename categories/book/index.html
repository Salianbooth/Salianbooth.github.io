存储过程

存储过程（Stored Procedure） 是一段预编译的 SQL 代码，保存在数据库中，可以重复调用。你可以将存储过程理解为一个可以执行的 SQL 脚本，适用于需要重复使用或复杂的业务逻辑操作。

本身就是用来封装一段SQL语句，进行复用，我的理解就是这个是可以没有return的函数（但是这只是粗浅的理解，实际上存储过程和函数区别和使用场景有着挺大的不同的）

可以包含多种 SQL 语句，适合更复杂的操作，包括插入、更新、删除和事务控制。存储过程可以处理数据修改、事务管理等复杂

  • 存储过程：可以接受三种类型的参数：
    • IN：传入参数，存储过程内部只能读取。
    • OUT：输出参数，存储过程内部修改后返回给调用者。
    • INOUT：既可以传入，又可以返回值。

基础语法

  • procedure_name：存储过程的名称。
  • IN、OUT、INOUT：参数的类型，分别表示输入、输出、输入输出参数。
  • parameter_name：参数的名称。
  • datatype：参数的数据类型（如 INT、VARCHAR 等）。
  • BEGIN ... END：存储过程的主体，包含具体的 SQL 语句。

存储过程的优点：

  1. 提高性能：存储过程在创建时被编译，执行时效率较高；而且通过减少客户端和服务器之间的通信，可以提升执行效率。
  2. 代码重用：存储过程可以多次调用，减少了重复代码。
  3. 封装复杂逻辑：复杂的业务逻辑可以被封装在存储过程内，客户端只需调用存储过程，而无需关心其内部实现。
  4. 安全性：通过存储过程可以控制用户对数据库的访问权限，避免直接执行 SQL 操作。
  5. 事务支持：存储过程内部可以控制事务，确保数据的完整性和一致性。

缺点：

  1. 调试困难：相比应用程序中的代码，调试存储过程中的逻辑更加困难。
  2. 可移植性差：不同的数据库管理系统（如 MySQL、PostgreSQL、Oracle）对存储过程的支持存在差异，代码的移植性较差。
  3. 维护复杂：随着存储过程的数量增加，数据库中的逻辑复杂度也会增加，维护变得更加困难。

适用场景：

  1. 批量处理：存储过程适合批量更新或操作多个表的场景。
  2. 业务逻辑封装：将业务逻辑集中在数据库端，通过存储过程控制业务流程，如订单处理、库存管理等。
  3. 事务处理：多步数据库操作中需要确保数据一致性时，存储过程可以通过事务控制完成复杂操作。
  4. 复杂查询：需要执行多个查询、插入、更新或删除操作时，可以将这些操作封装在存储过程内。

事务处理

在复杂的操作中，存储过程通常会使用事务来确保数据的一致性。

当我们在进行存储过程时，假设这个过程中，数据库出现故障，那会怎么办呢？数据库中有可能会出现我们所不知道的空行或者不完整的表单。如何解决这种问题？这时候就需要使用事务处理。

那么事务处理到底是什么呢？事务处理是一种机制，用来管理必须成批执行的SQL操作。

使用事务处理，可以保证一组操作不会中途停止，它们要么完全执行，要么完全不执行。如果发生错误，则进行回退。

事务有四个重要的特性，称为 ACID 特性：

  • 原子性（Atomicity）：事务中的所有操作要么全部完成，要么全部不完成。任何一个操作失败，整个事务就会回滚到事务开始前的状态。
  • 一致性（Consistency）：事务执行前后，数据库的完整性约束没有被破坏。
  • 隔离性（Isolation）：并发执行的事务彼此之间不应相互影响，每个事务的中间状态对其他事务是不可见的。
  • 持久性（Durability）：一旦事务提交，其对数据库的更改是永久性的，即使系统崩溃也不会丢失。

MySQL 提供了一些用于控制事务的语句：

  • START TRANSACTION 或 BEGIN：开启一个新的事务。
  • COMMIT：提交事务，将所有操作的更改保存到数据库中。
  • ROLLBACK：回滚事务，撤销自上次 START TRANSACTION 以来的所有操作。
  • SAVEPOINT savepoint_name：设置一个事务保存点，可以在回滚时回到该保存点。
  • ROLLBACK TO SAVEPOINT savepoint_name：将事务回滚到指定的保存点。

例子

假设我们有两个账户的余额记录在表 accounts 中，我们想要执行一次资金转账操作。如果任何一步失败，整个操作应该回滚。

  1. 从 Alice 的余额中扣除 200。
  2. 向 Bob 的余额中增加 200。

如果任何一步失败，则应回滚。

语句解析：

事务处理的好处

  • 数据一致性：通过原子性和隔离性保证操作不会因失败而导致数据不一致。
  • 错误处理：可以在事务内捕获错误并选择是否回滚。
  • 并发控制：通过隔离级别管理并发操作对数据的影响。

游标

在 MySQL 中，游标（Cursor）是用于遍历查询结果集的数据库对象。它可以逐行地访问查询的每一行记录，非常适合在存储过程或触发器中处理复杂的逻辑，例如批量操作、逐行处理数据等。

游标的特点

  1. 逐行处理：游标允许在存储过程中逐行访问查询结果集，而不是一次性地返回整个结果。
  2. 状态管理：游标有不同的状态（如打开、关闭、结束）来控制对数据的访问。
  3. 适合复杂逻辑：在需要对查询结果进行逐行处理或复杂计算的情况下，游标非常有用。

使用游标的基本步骤

  1. 声明游标：定义游标并关联一个查询语句。
  2. 打开游标：打开游标以开始读取数据。
  3. 读取数据：使用 FETCH 语句从游标中逐行提取数据。
  4. 关闭游标：完成操作后，关闭游标释放资源。

游标的示例

假设有一个表 employees，结构如下：

employee_id first_name last_name salary
1 John Doe 5000
2 Jane Smith 6000
3 Bob Brown 7000

我们将编写一个存储过程，逐行遍历这个表的数据，并在控制台输出每个员工的姓名和薪水。

游标的工作流程

  1. 声明游标：在存储过程中定义游标 employee_cursor，该游标执行一个 SELECT 查询，获取 employees 表中的所有记录。

  2. 声明处理程序：使用 DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1; 来声明一个异常处理程序，当游标到达结果集的末尾时，会将 done 变量设为 1，从而结束循环。

  3. 打开游标：通过 OPEN employee_cursor; 打开游标，准备逐行读取数据。

  4. 读取数据并处理：使用 FETCH 语句从游标中提取数据到变量中，直到 done 变量被设置为 1 时结束循环。

  5. 关闭游标：完成读取操作后，通过 CLOSE employee_cursor; 关闭游标，释放资源。

详细解析

  • DECLARE employee_cursor CURSOR FOR ...：定义一个游标 employee_cursor，其结果集为 SELECT employee_id, first_name, last_name, salary FROM employees;。

  • DECLARE CONTINUE HANDLER FOR NOT FOUND ...：定义一个处理程序，处理游标读取到结果集末尾的情况，设置 done 变量为 1 以退出循环。

  • OPEN employee_cursor：打开游标，使其可以读取数据。

  • FETCH employee_cursor INTO ...：逐行从游标中读取数据，并将其存入之前声明的变量中。

  • IF done = 1 THEN LEAVE read_loop;：检查 done 是否为 1，如果是，则退出循环（表示结果集已经读取完毕）。

  • CLOSE employee_cursor：关闭游标释放资源。

游标的应用场景

  1. 批量更新/插入：当需要对结果集的每一行进行复杂处理并更新时，例如计算薪水、调整库存等，游标非常有用。
  2. 逐行处理逻辑：一些业务逻辑可能要求对表中的每一行数据进行检查和处理，这些操作很难通过简单的 SQL 语句实现，这时游标就派上用场了。
  3. 复杂报告生成：当需要根据表中的数据生成详细报告时，游标可以逐行访问数据，汇总和计算信息。

注意事项

  1. 性能问题：游标逐行处理数据，在大数据集上效率较低。如果可能，尽量使用批量操作和集合操作来代替游标。
  2. 资源管理：游标需要显式地打开和关闭，否则可能会导致资源泄露。

总结

  • 游标 是在 MySQL 中遍历查询结果集的一种工具，适用于存储过程中需要逐行处理数据的场景。
  • 通过游标，我们可以逐行读取、处理、更新数据，适合复杂的业务逻辑和逐步操作。
  • 但由于游标可能带来性能开销，在可能的情况下，应优先考虑批量操作或其他替代方法。

  2. 有助于编译器优化：

  1. 代码膨胀：
    • 如果内联函数体较大且被多次调用，会导致生成的二进制代码膨胀，增加可执行文件的大小。

适用场景

  • 简单、频繁调用的函数：适用于函数体小且频繁调用的函数，如访问器（getter）和设置器（setter）。
  • 时间关键代码：在性能要求较高的代码中，可以使用内联函数减少函数调用开销。

使用注意事项

  1. 避免过度使用:

  2. 递归函数:
    • 递归函数通常不适合作为内联函数，因为展开递归调用会导致无限膨胀。

9.3.6 容器操作会使迭代器失效

容器操作及其对迭代器失效的影响

  1. vector 和 string：
    • 增加元素：当 vector 或 string 需要重新分配内存时，所有的迭代器、引用和指针都会失效。
    • 删除元素：从 vector 或 string 中删除元素时，指向删除点及其后的迭代器、引用和指针都会失效。
  2. deque：
    • 增加元素：在头部或尾部增加元素时，所有迭代器都会失效。
    • 删除元素：在头部或尾部删除元素时，所有迭代器都会失效。
    • 中间插入或删除：只会使指向操作点及其后的迭代器失效。
  3. list 和 forward_list：
    • 由于 list 是双向链表，forward_list 是单向链表，它们的节点在内存中不连续，增加或删除元素时，指向其他节点的迭代器不会失效，除非是指向被删除节点的迭代器。
  4. associative containers (如 set, map 等)：
    • 增加或删除元素时，指向其他元素的迭代器不会失效，除非是指向被删除元素的迭代器。
  5. unordered containers：
    • 插入元素可能会导致容器重新哈希，从而使所有迭代器失效。
    • 删除元素时，指向其他元素的迭代器不会失效，除非是指向被删除元素的迭代器。

9.4 vector是如何增长的

1. 检查是否需要扩容

当我们向vector中添加元素时，首先会检查当前的大小是否已经达到了容量。如果没有，则元素可以直接添加，无需分配新的内存。

2. 确定新的容量

如果size已经等于capacity，则vector需要增加容量。新的容量通常是现有容量的两倍，但这并非标准规定的行为，而是一种常见的实现策略。这个策略的优点是减少了频繁分配内存的开销。

3. 分配新内存并复制旧数据

vector会分配一块新的内存空间，其大小等于新的容量。然后，它会将旧内存中的元素逐个复制到新内存中。这是因为标准要求元素要在与它们被销毁的地方不同的内存位置构造。复制完成后，旧的内存会被释放。

4. 调整内部指针

新内存中的元素构造完成后，vector的内部指针和相关数据成员会更新，以反映新的容量和内存地址。

5. 更新容量和大小

扩容完成后，vector的capacity会被更新为新的容量，而size会增加到包含新元素的大小。

map和unordered-map的区别

1. map

  • 底层实现: map 是基于平衡二叉搜索树（通常是红黑树）实现的。
  • 元素有序性: map 会根据键值的大小自动对元素进行排序，键的顺序是严格有序的（按照小到大的顺序，或根据自定义的比较函数）。
  • 查找、插入、删除的时间复杂度: 平均情况下为 O(log n)，最坏情况也为 O(log n)。
  • 内存占用: 由于平衡二叉树的结构，map 的内存开销相对较大。

2. unordered_map

  • 底层实现: unordered_map 是基于哈希表实现的。
  • 元素有序性: unordered_map 中的元素没有固定顺序，键值对的顺序与插入顺序无关。
  • 查找、插入、删除的时间复杂度: 平均情况下为 O(1)，最坏情况下为 O(n)，但最坏情况较少发生（如出现哈希冲突或不良的哈希函数）。
  • 内存占用: unordered_map 由于哈希表需要额外的空间来处理冲突，可能会占用更多的内存。

选择指南

  • 如果需要对键进行排序或者需要按顺序遍历元素，选择 map。
  • 如果不需要顺序，且对性能要求较高，选择 unordered_map。

三法则（Rule of Three）

三法则指出，如果一个类需要自定义以下任意一个函数，通常也需要自定义另外两个：

  1. 拷贝构造函数 (Copy Constructor)：
    • 用于创建一个对象的副本，如MyClass obj2 = obj1;。
  2. 拷贝赋值运算符 (Copy Assignment Operator)：
    • 用于将一个对象赋值给另一个已存在的对象，如obj2 = obj1;。
  3. 析构函数 (Destructor)：
    • 用于清理对象在其生命周期内分配的资源。

这些函数通常一起实现是因为它们都涉及到类的资源管理。例如，如果类涉及到动态内存分配，在一个函数中没有适当地管理内存会导致资源泄漏、双重释放等问题。通过遵循三法则，可以确保对象的安全使用。

五法则（Rule of Five）

五法则是三法则的扩展，考虑了C++11及更高版本中的移动语义。除了三法则中的三个函数外，还增加了两个与移动操作相关的函数：

  1. 移动构造函数 (Move Constructor)：
    • 用于将资源从一个临时对象（右值）“移动”到另一个对象，而不进行拷贝操作。例如：MyClass obj3 = std::move(obj1);
  2. 移动赋值运算符 (Move Assignment Operator)：
    • 用于将一个临时对象（右值）赋值给另一个已存在的对象，并“移动”资源，如obj3 = std::move(obj1);。

这两个移动操作通常用于优化性能，避免不必要的拷贝，特别是在涉及大型数据结构或资源时。遵循五法则可以确保类在拷贝和移动操作中都能正确处理资源。

在C++中，左值（lvalue） 是指那些可以取地址的表达式，即持久存在的内存位置，如变量名。而 右值（rvalue） 则是不能取地址的临时对象或表达式的值。

  • 左值：int x = 5; x 是左值，因为 x 是一个变量，可以取地址。

14.1 基本概念

运算符重载是C++中一个强大的特性，它允许程序员定义或修改C++中的运算符（如 +, -, *, == 等）以处理自定义的类型（例如类和结构体）。运算符重载使得用户定义的类型可以像内置类型一样方便地使用。

主要内容包括：

  1. 运算符函数：
    • 运算符重载是通过定义一个特殊的函数来实现的，这个函数称为“运算符函数”。
    • 运算符函数的名字是 operator 后跟运算符符号，例如 operator+、operator==。
  2. 重载的运算符的规则：
    • 重载运算符必须是成员函数或友元函数。
    • 重载运算符的操作数必须包括至少一个用户定义的类型（如类的对象）。
    • 不能改变运算符的优先级、结合性或默认的操作数数量。
    • 不能重载内置类型的运算符。
  3. 友元函数与成员函数：
    • 对于二元运算符（如 +，-），可以选择将它们重载为友元函数或成员函数。
    • 如果运算符函数是成员函数，它的左操作数绑定到 this 指针，右操作数作为参数传递。
    • 如果运算符函数是友元函数，两个操作数都作为参数传递。
  4. 输入/输出运算符的重载：
    • 常见的运算符重载是输入（>>）和输出（<<）运算符，用于自定义类的输入和输出格式。
    • 这些通常实现为友元函数，以便直接访问类的私有成员。

抽象类的特点：

  1. 纯虚函数（Pure Virtual Function）：

    • 纯虚函数是一个在基类中声明但没有定义的函数，它使用 = 0 来表示。例如：

      virtual void display() = 0;

    • 任何包含至少一个纯虚函数的类就是一个抽象类。

  2. 不能实例化：

    • 由于抽象类包含未实现的纯虚函数，不能直接创建抽象类的对象。例如，假设 Base 是一个抽象类：

      Base obj; // 错误：不能实例化抽象类

  3. 用于接口设计：

    • 抽象类常用于设计接口，让子类实现具体功能。它提供了一种在基类中定义通用行为并强制子类实现特定功能的方式。

  4. 子类实现：

    • 继承抽象类的子类必须实现所有的纯虚函数，否则该子类也将成为一个抽象类。

15.5类的权限控制

1. public（公共成员）

  • 描述：使用 public 关键字声明的成员可以被任何地方访问。
  • 应用场景：通常用于定义类的接口（即希望外部代码可以直接访问和调用的成员）。

2. protected（受保护成员）

  • 描述：使用 protected 关键字声明的成员只能在类内部及其派生类中访问，而不能在类外部访问。
  • 应用场景：通常用于基类和派生类之间共享数据，但不希望这些数据暴露给类外部的任何部分。

3. private（私有成员）

  • 描述：使用 private 关键字声明的成员只能在类的内部访问，类的外部和派生类都不能直接访问。
  • 应用场景：用于隐藏类的实现细节，仅通过公共接口与外部交互。

类的权限控制在派生类中的表现：

  • 当一个类继承自另一个类时，基类中的访问控制符如何影响派生类访问基类成员是一个需要注意的地方。
  • 当继承方式为 public 时：
    • 基类的 public 成员在派生类中仍然是 public。
    • 基类的 protected 成员在派生类中仍然是 protected。
    • 基类的 private 成员不能在派生类中访问。
  • 当继承方式为 protected 时：
    • 基类的 public 成员在派生类中变为 protected。
    • 基类的 protected 成员在派生类中仍然是 protected。
    • 基类的 private 成员不能在派生类中访问。
  • 当继承方式为 private 时：
    • 基类的 public 和 protected 成员在派生类中都变为 private。
    • 基类的 private 成员不能在派生类中访问。

struct 和 class 的区别：

1. 默认访问控制：

  • class：默认的成员和基类继承权限是 private。
  • struct：默认的成员和基类继承权限是 public。

2. 继承默认权限：

  • class：继承默认是 private。
  • struct：继承默认是 public。

3. 其他方面的相似性：

  • 构造函数、析构函数、成员函数：class 和 struct 都可以定义构造函数、析构函数和成员函数。
  • 继承、多态性、模板：两者都可以用于继承、实现多态性、以及用于模板编程。
  • 成员变量：无论是 class 还是 struct，都可以包含成员变量，并且成员变量的行为是一致的。
  • 操作符重载：两者都可以重载操作符。

4. 语义上使用上的习惯：

在现代C++编程中，通常有以下习惯：

  • struct：一般用于定义具有简单数据结构的数据类型，所有成员默认 public。常用于表示类似 C 语言中的数据结构，主要用于存储数据而不涉及复杂的行为或封装。
  • class：通常用于定义具有更复杂行为、封装数据和逻辑的对象，主要用于面向对象编程，强调封装性、继承性、多态性等。

  1. 减少代码膨胀：模板会在每次使用不同类型时生成新的实例化代码，这可能导致生成的可执行文件变大。通过控制实例化，我们可以限制实例化的数量。

    • 使用 template 关键字并提供模板参数，这会导致编译器生成模板的具体代码。

  2. 显式实例化声明（Explicit Instantiation Declaration）：

    • 使用 extern template 关键字，告诉编译器在当前翻译单元（通常是一个 .cpp 文件）中不要生成模板实例化代码，而是期望这些代码在其他地方已经生成。这种机制可以避免在多个文件中重复生成模板实例化代码。
